# Product Catalog MVP Blueprint

## Catalog layers

### Provider Product

Raw hidden synchronized supply record: provider/service ID, raw name, cost/currency, availability/status, input metadata, min/max/step, optional raw category/image, last sync, and change state. It is never customer-visible by import alone.

### Store Category

Tenant-owned customer section. MVP example: `Games`. It owns display name, description, image, icon, banner, sort order, active state, and publication/visibility.

### Store Product

Tenant-owned branded page. MVP example: `PUBG Mobile`. It owns category, customer name/description, image/icon/banner, sort order, active/publication state, source type `provider`, and fulfillment type `provider_api`.

### Product Package / Variant

Sellable option under a Store Product. MVP examples: `60 UC`, `325 UC`, `660 UC`. It owns customer package name, versioned provider mapping, reviewed inputs/limits, pricing reference, order, and active state. Packages inherit the parent visual by default.

## Publishing workflow

1. Provider sync imports raw hidden services.
2. Catalog Manager reviews cost/currency/status/inputs/limits/metadata.
3. Select `ADD_AS_PACKAGE`, create/select Games and PUBG Mobile, map each provider service to a package.
4. Configure tenant visuals, customer names/descriptions, sort/visibility, input definitions, and tier price.
5. Preview storefront/quote.
6. Tenant Admin or approved Publisher confirms publication.
7. Publication creates a versioned customer-facing snapshot and audit event.

No bulk/full-catalog customer publication exists in MVP.

## Publishing modes

- **`ADD_AS_PACKAGE`:** implemented reference path for multiple game denominations beneath one parent product.
- **`ADD_AS_STANDALONE_PRODUCT`:** represented in contract/schema for later SMM/recharge/live-chat services with unique form/quantity; not enabled as a customer MVP path.

## Dynamic input fields

Versioned field definition contains stable key, type, required flag, label, placeholder, help, validation pattern, min/max/step, default, options, customer visibility, provider-only flag, and mapped provider payload key.

Supported model types: text, number, quantity counter, dropdown, radio, textarea, phone, email, password, hidden provider metadata.

MVP enables Player ID plus only the selected provider's required server/region text/dropdown. Password input is excluded unless separately approved. Hidden provider values are generated by the system, never customer-controlled.

Provider input changes create review and cannot silently alter a live form/order snapshot.

## Visual customization

- Tenant category/product assets override provider metadata.
- Provider image is an optional reviewed fallback candidate only.
- No uncontrolled hot-linking; approved asset uses tenant-aware object/storage/CDN policy.
- Audit image/icon/banner/name/description/sort/visibility changes.
- Historical order snapshots reference the relevant catalog/presentation version without requiring current product to remain active.

## Lifecycle rules

- Draft/reviewed/published/suspended/unpublished states are explicit.
- Disabled/removed provider service suspends new purchase; does not delete product mapping or old orders.
- Catalog/product/package active state, provider availability, module/tenant state, price readiness, and permission are separate gates.
